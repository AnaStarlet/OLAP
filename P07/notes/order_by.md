# Обоснование ORDER BY в ClickHouse

## Что такое ORDER BY в ClickHouse

ORDER BY в MergeTree — это не уникальный ключ, как PRIMARY KEY в Postgres.
Это порядок, в котором строки физически лежат на диске. По нему ClickHouse
решает, какие блоки читать при фильтрации. Уникальность он не гарантирует:
дубли возможны, и мы защищаемся от них через TRUNCATE перед загрузкой.

## Ограничение: только не-Nullable колонки

ClickHouse запрещает Nullable-колонки в ORDER BY (ошибка `Sorting key
contains nullable columns`). Поэтому в фактах мы оставили в ключе только
не-Nullable поле — `date_id` (Int32). В `dim_employee` — `employee_id`,
в `dim_date` — `date_id`.

## Почему именно эти колонки

В бизнес-вопросах из паспорта мы фильтруем:

- по дате продажи (оборот за январь, средний чек по месяцам);
- по магазину (оборот по магазинам);
- по категории товара (оборот по категориям).

`date_id` стоит первым в ORDER BY у всех фактов — по нему идёт большинство
запросов. Это позволяет ClickHouse отсекать ненужные блоки и читать меньше
данных. `store_id` и `product_id` — Nullable, их в ключ положить нельзя, но
они остаются в таблице и используются в JOIN.

Для справочников порядок по первичному ключу (`store_id`, `product_id` и т.д.) —
стандартный приём: JOIN по id идёт быстро, потому что данные лежат рядом.
