# З09. Сводная таблица sales_by_store_month

## График

Будущий виджет на дашборде (З10): оборот по магазинам по месяцам —
линейный график, по оси X месяцы, по оси Y оборот, каждая линия — магазин.

## Одна строка сводки

Одна строка сводки = один месяц + один магазин.

Это НЕ то же, что «одна строка факта = одна позиция чека».

Поля сводки:

- year — год
- month_num — номер месяца (1–12)
- store_id — id магазина
- store_name — название магазина
- amount_sum — сумма total_amount за этот месяц и магазин

## Метрика

В сводке считается та же метрика, что в canonical_metric.sql:
SUM(total_amount) без каких-либо дополнительных фильтров.
Это нужно, чтобы на З11 число на карточке дашборда совпало с эталонным SQL.

## Как пересчитать сводку

После каждой загрузки детальных данных сводка пересобирается полностью:

    TRUNCATE TABLE olap.sales_by_store_month;
    INSERT INTO olap.sales_by_store_month
    SELECT ... FROM olap.fact_sales FINAL ...

Скрипт: sql/summary_fill.sql.

100 000 строк ClickHouse агрегирует меньше чем за секунду,
поэтому полный пересчёт проще и надёжнее инкрементального.

## Сверка

- Сумма по детальной таблице: SELECT sum(total_amount) FROM olap.fact_sales FINAL
- Сумма по сводке: SELECT sum(amount_sum) FROM olap.sales_by_store_month FINAL

Числа совпадают: 3557661372.99.

По январю 2024 тоже совпадают: 45313454.57 в обеих таблицах.
