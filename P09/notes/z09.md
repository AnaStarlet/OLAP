\# З09. Сводная таблица sales\_by\_store\_month



\## График



Будущий виджет на дашборде (З10): оборот по магазинам по месяцам —

линейный график, по оси X месяцы, по оси Y оборот, каждая линия — магазин.



\## Одна строка сводки



Одна строка сводки = один месяц + один магазин.



Это НЕ то же, что «одна строка факта = одна позиция чека».



Поля сводки:



\- year — год

\- month\_num — номер месяца (1–12)

\- store\_id — id магазина

\- store\_name — название магазина

\- amount\_sum — сумма total\_amount за этот месяц и магазин



\## Метрика



В сводке считается та же метрика, что в canonical\_metric.sql:

SUM(total\_amount) без каких-либо дополнительных фильтров.

Это нужно, чтобы на З11 число на карточке дашборда совпало с эталонным SQL.



\## Как пересчитать сводку



После каждой загрузки детальных данных сводка пересобирается полностью:



&#x20;   TRUNCATE TABLE olap.sales\_by\_store\_month;

&#x20;   INSERT INTO olap.sales\_by\_store\_month

&#x20;   SELECT ... FROM olap.fact\_sales FINAL ...



Скрипт: sql/summary\_fill.sql.



100 000 строк ClickHouse агрегирует меньше чем за секунду,

поэтому полный пересчёт проще и надёжнее инкрементального.



\## Сверка



\- Сумма по детальной таблице: SELECT sum(total\_amount) FROM olap.fact\_sales FINAL

\- Сумма по сводке: SELECT sum(amount\_sum) FROM olap.sales\_by\_store\_month FINAL



Числа совпадают: 3557661372.99.



По январю 2024 тоже совпадают: 45313454.57 в обеих таблицах.
