# З08. Ключ сортировки и партиция

## ORDER BY

`ORDER BY` в ClickHouse — не уникальный ключ, как PRIMARY KEY в Postgres.
Это порядок хранения строк на диске и ключ дедупликации для `ReplacingMergeTree`.

- `fact_sales` — `sale_id`
- `fact_visits` — `visit_id`
- `fact_interest` — `interest_id`
- `fact_loyalty` — `loyalty_id`
- `fact_logistics` — `shipment_id`
- `fact_inventory` — `inventory_id`
- справочники — по своему id

Ключ выбран так, потому что он уникален по смыслу («одна строка = одна сущность
или одно событие»), используется в JOIN, не Nullable.

## Партиция

Для `fact_sales` сделана партиция по месяцу:

    PARTITION BY intDiv(date_id, 100)

`date_id` имеет вид `20240115`. Деление на 100 даёт `202401` — год и месяц.
Каждый месяц лежит отдельным куском.

Почему именно по месяцу:

- все три бизнес-вопроса из паспорта фильтруют по месяцу или кварталу —
  оборот за январь, категории за квартал, средний чек по месяцам;
- партиция по месяцу соответствует типичным фильтрам;
- целый месяц можно удалить одной командой `DROP PARTITION`.

## Разница ORDER BY и PARTITION BY

- `ORDER BY` — упорядочивает строки внутри куска и задаёт ключ дедупликации.
- `PARTITION BY` — разбивает таблицу на отдельные куски по месяцам.

Это два независимых рычага, могут применяться одновременно.

## Что не говорим про ORDER BY

`ORDER BY` — не уникальный ключ как PRIMARY KEY в Postgres.
Две строки с одинаковым ключом могут временно существовать до фонового мержа.
