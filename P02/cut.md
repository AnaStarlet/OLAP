1. Кластер ClickHouse — не делаем. Витрина в одном файле DuckDB. На миллионах строк запросы тормозят, параллельные пользователи мешают друг другу.

2. Kafka / потоковая загрузка — не делаем. Данные грузятся пакетно, ночью. Отчёт «за сегодня» невозможен, real-time-дашборда нет.

3. ML-прогноз спроса — не делаем. Витрина отвечает только «что было», а не «сколько продастся завтра». Планирование закупок — вручную.

4. SCD2 для dim_store и dim_customer — не делаем. Оставляем только SCD1. Если магазин переехал, старые продажи «прилипнут» к новому адресу — региональная динамика искажена.

5. Возвраты — не делаем. В сырье нет признака is_return, поэтому «оборот без возвратов» = обычный оборот. Если бы возвраты были — отчёт завышал бы выручку.

6. Справочник поставщиков — не делаем. В dim_product есть supplier_id, но без названия. Разрез по поставщикам неудобен.

7. Праздники в dim_date — не делаем. Сезонность считается только по месяцу и кварталу, без праздников.
